# 关卡系统迭代：问题、经历与需求

## 一、项目背景

这是一个 tile 消除品类游戏。有两层数据结构：

- **地形 (Terrain)**：牌的物理布局，包括位置、层级、叠压依赖关系
- **牌局 (Board)**：在地形之上，为每张牌分配了具体花色。玩家实际游玩的是牌局

**生成算法**的任务是：给定地形，输出牌局（花色分配）。

---

## 二、生成算法 v1：质量不足

早期使用第一版生成算法批量产出牌局，用纯贪心策略验证，根据 cost、胜负、压力等指标按需筛选，投入游戏使用。

问题：对关卡缺乏精确掌控。

---

## 三、生成算法 v2：ReverseGen (CostLadder)

### 3.1 设计思路

将贪心策略视为最优解路径——即贪心每步选择 cost 最小的 triple，这条贪心路径就是"最优消除序列"。基于这个前提，反向设计算法：

- **输入**：Cost 数组（每步的目标难度）
- **输出**：花色分配，使得贪心模拟产生的实际 cost 链严格匹配输入的 Cost 数组

通过控制 Cost 数组的特征（升降趋势、连续同值、r 值等），间接控制玩家体验——难度曲线、连消节奏、甚至通过控制 r 值精确控制玩家在第几步 dock 满导致死亡。

### 3.2 核心机制

1. **Cost 定义**：`cost = |depSet \ collectedIds|`。消除一个 triple 需要释放多少尚未释放的依赖。这是算法唯一的决策依据。

2. **贪心选择**：每步选 cost ≥ target 的第一个候选。

3. **黑名单封杀**：cost ≤ 选中 triple 的候选全部永久封杀。没有黑名单，贪心会退化为永远选最便宜的，cost 链毫无起伏。

4. **池化**：连续同 cost 步骤在同一快照下多选，避免"同伴互杀"。

5. **抢救**：候选耗光时从黑名单尾部找回。

### 3.3 结果

算法产出基本满足 `Cost 数组 ≈ 实际 simcost 数组`，匹配率很高。从表象看，似乎实现了精确控制。

---

## 四、核心谬误的发现

### 4.1 贪心 ≠ 最优

ReverseGen 建立在"贪心是最优解路径"这个前提上。但实际上，用 DFS 求解器甚至一些莽撞的随机策略，都能轻松通过贪心算法判定为"无法通过"的关卡。

### 4.2 谬误的本质

问题不在于 triple-step 抽象与 tile-click 真实状态空间之间的粒度差异。实际上，在贪心选择的框架下，click 必然导向 triple——两者基本等价，压缩是合理的。

真正的问题在于：

> **由于牌局依赖关系的复杂性，当前局面下的局部最优解（低 cost、低 dock 压力）可能导向全局失败。而当前局面下暂时的劣质解（高 cost、高 dock 压力）才可能是全局正解。**

虽然前者（贪心）"正解概率"可能更高，但概率不是我们要的。我们要的是**确定的、明了的控制**。

### 4.3 后果

既然贪心路径不等于真实最优路径，那么通过 Cost 数组控制贪心模拟结果 → 间接控制玩家体验 这条链路就不成立。因为玩家（或 DFS 求解器）走的不是贪心路径，而是真实最优路径。

---

## 五、关卡系统迭代的真实需求

### 5.1 核心要求

对牌局实现**精确的逻辑化控制**，而非概率性的、评分式的模糊控制。具体包括但不限于：

| 控制维度 | 含义 |
|----------|------|
| 可解性 | 牌局是否数学上真正有解（不是贪心判定，是 DFS 判定） |
| 死亡点 | 如果不可解，在第几步、哪些位置会死，死几次 |
| 难度 | 不靠权重评分，而是结构性的、可证明的难度特征 |
| 博弈点 | 某一步有几个分支选择，哪个分支正确，分支间的辨识难度 |

### 5.2 对算法的要求

- **确定性**：输入 → 输出，不依赖随机、权重、评分。像 ReverseGen 的 `costArray → costLog` 那样精确可控。
- **命中核心逻辑**：不是堆砌复杂的策略层，而是找到像"cost"那样简单、清晰、有效的核心机制。
- **可证明性**：算法的产出可以被验证——不是"大概率满足"，而是"确定满足"。

---

## 六、Triple 依赖图分析

### 6.1 目的

在暂时没有明确的新算法方案的情况下，对地形和 triple 之间的静态关系进行深度分析，寻找灵感或作为新算法的依据。

### 6.2 内容

构建了所有 triple 之间的偏序关系图（95k 节点，436M 边）。核心关系：

```
B ≺ A  ⟺  B.depSet ⊆ A.depSet  且  B 与 A 不共享 tile
```

- 偏序关系是**纯逻辑的**（集合包含），不是加权评分
- 依赖深度是**纯拓扑的**（最长前驱链），不是调参
- 瓶颈 tile 是**可精确计算的**（出现在多少个 triple 的 depSet 中）

### 6.3 定位

依赖图是一个参考工具，而非强制要在后续算法中使用的组件。核心目标是完成关卡逻辑化的确定控制——为此需要找到其中最为核心的、有效的、命中本质的逻辑和策略。
