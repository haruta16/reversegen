# Phase A：牌局批量分析与结构特征发现

## 一、目标

建立「牌局 DAG 结构特征 → 牌局性质（可解性、死亡点、分支结构）」之间的映射关系，为新生成算法提供确定性的设计依据。

---

## 二、做了什么

### 2.1 求解器框架移植（C# → TypeScript）

在 `src/solver/` 下建立了完整的牌局分析框架，核心模块：

| 模块 | 功能 | 对应 C# |
|------|------|---------|
| `offline-game.ts` | 真实游戏规则引擎：Collect → CheckDockMatch → UpdateTilesState。RuntimeDependencies 动态计算 | `OfflineGame.cs` |
| `solver-dfs.ts` | DFS 求解器，状态记忆化 + 死路剪枝，动作排序（清除 > 配对 > 解锁量） | `SolverRunner.cs` |
| `solver-greedy.ts` | 贪心求解器：每步选成本最低、dock 压力最小的合法移动 | — |
| `solver-random.ts` | 随机蒙特卡洛：测量解空间宽度（50 次不同种子） | — |

**关键差异与 ReverseGen**：求解器使用**动态 RuntimeDependencies**（tile 级别的真实依赖关系），而非 ReverseGen 的静态传递闭包 `depSet`。这保证了分析结果的真实性。

### 2.2 色组 DAG 构建

在 `src/analysis/board-dag.ts` 中，对每个牌局构建**色组级 DAG**：

- 节点 = 一个花色组（包含 k 张同色 tile）
- 边 A → B = A 组中至少有 1 张 tile 是 B 组中某 tile 的直接依赖
- 提取特征：色组数、边数、最长链长度、并行组数、平均 depSet 大小

这个 DAG 可以从牌局**直接计算**，不需要跑 DFS。

### 2.3 批量分析

- 分析对象：135 个地形 × 每个取 2 个 replay code ≈ 200 个线上牌局
- 每个牌局运行：DFS 求解器（10s 超时）、贪心求解器、随机蒙特卡洛（50 次）
- 提取特征：色组分布、依赖深度、贪心路径压力、色组 DAG 结构

## 三、核心发现

### 3.1 宏观数据

| 指标 | 值 | 含义 |
|------|-----|------|
| 分析牌局数 | 200 | 覆盖 100 种地形 |
| DFS 可解 | 196 (98%) | 绝大多数牌局数学上有解 |
| 贪心可解 | 33 (16.5%) | **ReverseGen 的前提在 83.5% 的情况下不成立** |
| 贪心失败、DFS 成功 | 163 (81.5%) | 这是**常态**，不是例外 |
| 随机策略平均胜率 | 0.2% | 197/200 的牌局随机胜率为 0% |

### 3.2 贪心失败 vs 贪心成功：DAG 特征对比

这是最重要的分析。问的是：**什么结构特征让贪心策略迷路？**

| 特征 | 贪心失败 (n=163) | 贪心成功 (n=33) | 比值 |
|------|-----------------|-----------------|------|
| **dagEdgeCount（色组 DAG 边数）** | 88.5 | 49.5 | **1.79x** |
| colorCount（花色数） | 13.9 | 9.8 | 1.41x |
| avgDepClosureSize（平均传递依赖深度） | 6.2 | 4.5 | 1.38x |
| dagAvgDepSetSize（色组平均 depSet） | 24.3 | 21.5 | 1.13x |
| greedyAvgDock（贪心路径平均 dock） | 3.2 | 2.2 | 1.50x |
| greedyMaxDock（贪心路径最大 dock） | 7.0 | 5.6 | 1.26x |
| dfsStatesVisited（DFS 搜索状态数） | 4668 | 151 | **30.9x** |

**结论**：

- **dagEdgeCount** 是最强的区分信号。贪心失败的牌局，色组之间的依赖边更多（交织更密），贪心的局部最优（选 cost 最低的）在这种结构里必然偏离全局最优路径。
- 贪心成功的牌局结构相对"平坦"：颜色少、依赖边少、依赖浅。贪心策略在简单结构上是够用的。
- DFS 在贪心失败的牌局中需要探索 **30 倍以上的状态** 才能找到解（或判定无解），从侧面验证了这些牌局的复杂性。

### 3.3 DFS 可解 vs 不可解（n=4，数据有限）

| 特征 | 可解 (n=196) | 不可解 (n=4) | 比值 |
|------|-------------|-------------|------|
| colorCount | 13.2 | 21.0 | 0.63 |
| dagEdgeCount | 81.9 | 157.0 | 0.52 |
| dagParallelGroups | 0.2 | 0.0 | — |

不可解的牌局（n=4）表现出：更多花色、更多 DAG 边、零并行组。但由于只有 4 个不可解样本，这些相关性只是**方向性的参考**，不是确定的结论。

### 3.4 解空间宽度

随机策略胜率分布：

```
0%:        197 boards (98.5%)  ← 极窄路径，"谜题"牌局
1%-19%:      2 boards
20%-49%:     1 board
50%+:        0 boards
```

**绝大多数线上牌局的解空间极其狭窄。** 随机点击几乎必然失败。这说明这些牌局本质上是"谜题"——只有特定的消除序列才能通关。玩家（或求解器）必须精确选择每一步的 tile，容错空间几乎为零。

## 四、对关卡系统迭代的启示

### 4.1 dagEdgeCount 作为确定性控制指标

dagEdgeCount 是可直接从牌局计算的、确定性的、不依赖 DFS 的结构指标。它反映了**色组之间依赖关系的交织程度**，并且与贪心策略的成败、DFS 搜索复杂度呈明显的正相关。

这意味着：**如果你能在生成过程中控制 dagEdgeCount，你就能控制牌局的复杂度。**

### 4.2 特征方向性总结

| 控制目标 | 对应的 DAG 特征 | 方向 |
|----------|---------------|------|
| 牌局容易（贪心可解） | dagEdgeCount 低、colorCount 低、链长短 | 降低 |
| 牌局有博弈点（多条路径） | dagParallelGroups 高 | 提高 |
| 牌局为谜题（极窄路径） | dagEdgeCount 高、随机胜率 ≈ 0 | 提高 |
| 牌局容错（宽路径） | 随机胜率 > 0 | 降低 dagEdgeCount、提高并行度 |
| 牌局不可解 | dagEdgeCount 极高、parallelGroups = 0、depSet 大 | 需更多不可解样本验证 |

### 4.3 当前局限

1. **不可解样本太少（4/200）**：线上 replay 几乎都是可解的，导致无法对"不可解"特征做可靠分析。需要用 ReverseGen 或手动构造更多不可解牌局进行对比。

2. **色组 DAG 是粗粒度的**：当前只分析色组级别的依赖（A 的花色组是否阻塞 B 的花色组），没有分析色组内部 triple 之间的偏序关系。进一步细化需要构建 triple 级 DAG。

3. **correlation ≠ causation**：dagEdgeCount 和贪心失败之间有统计相关性，但还没有建立严格的"如果 dagEdgeCount > X 则贪心必定失败"这种确定性的充分条件。
